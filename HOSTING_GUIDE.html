LG Duel: host an Internet match from this PC

This project uses a dedicated native UDP server. The default game port is UDP 27960. TCP port forwarding is not needed.

Verified on June 10, 2026: server handshakes work on 127.0.0.1:27960 and 192.168.68.107:27960. The current public IPv4 address is 213.66.106.51. Public-IP loopback did not answer, so the Deco port forward and an external-player test are still required.

1. Start and verify the server

From /home/helmer-jagenmark/LG-duel:

./scripts/server-control.sh start
./scripts/server-control.sh status

A successful status check says OK: connected. It performs the real game handshake and receives an authoritative snapshot.

This PC is configured with an enabled user-level systemd service named lg-duel-server.service. It keeps the server independent of the terminal and restarts it after a crash.

Other commands:

./scripts/server-control.sh logs
./scripts/server-control.sh restart
./scripts/server-control.sh stop

To use another port, pass it when starting, for example ./scripts/server-control.sh start 27961.

2. Allow the Ubuntu firewall

The UFW service is installed/enabled, but its effective packet rules require administrator access to inspect. Run:

sudo ufw status

If active, allow the game port:

sudo ufw allow 27960/udp comment 'LG Duel server'
sudo ufw status numbered

3. Forward UDP through the router

This network uses a TP-Link Deco router at 192.168.68.1. In the Deco mobile app, open More → Advanced → NAT Forwarding → Port Forwarding (wording varies by firmware), then add the rule below.

  1. Select this PC or enter its current LAN address: 192.168.68.107.
  2. Set external port 27960, internal port 27960, protocol UDP.
  3. Save/apply the rule.
  4. Reserve 192.168.68.107 for this PC under the Deco address-reservation/DHCP settings.

Do not place the PC in a DMZ and do not forward every port. Forward only UDP 27960.

4. Give friends the connection address

Get the current public IPv4 address:

curl -4 https://icanhazip.com

Friends start the client with:

./build/default/lg_duel_client 213.66.106.51 27960

Public IP addresses can change. Re-run curl -4 https://icanhazip.com before each test session and send friends the new value if it differs.

They must run a client built from the same project revision because the handshake checks the protocol version. On Windows, the executable may be under build\msvc\Debug\lg_duel_client.exe.

The host should connect locally with ./build/default/lg_duel_client 127.0.0.1 27960. Testing your own public IP from inside the same LAN may fail when the router lacks NAT loopback even though friends can connect.

5. Test from outside your network

UDP cannot be validated reliably by a generic web port checker. Have a friend run the actual client while the server log is visible:

./scripts/server-control.sh logs

When the handshake succeeds, the log reports Connected clients: 1 or 2. Both players press F3 to ready up.

Troubleshooting

  • Local probe fails: inspect .server/lg-duel-server.log and check whether another process owns UDP 27960 with sudo ss -lunp | grep 27960.
  • Local works, friends time out: verify the router rule says UDP, targets the current LAN address, and the UFW rule is present.
  • Router WAN address differs from public IP: the ISP may use CGNAT. Ask the ISP for a public IPv4 address, use native IPv6 if every player has it, or use a mesh VPN such as Tailscale/ZeroTier.
  • Only one friend can join: the prototype intentionally has two total player slots, including the host.
  • After reboot: the enabled user service starts with the desktop user session. Check it with ./scripts/server-control.sh status.

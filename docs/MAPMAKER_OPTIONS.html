Decision brief

Maps without building an editor empire.

LG Duel's arena is already a small set of axis-aligned 3D boxes and spawn points. That makes simple map creation a small-to-medium feature—provided the format stays narrow and the renderer, collision, combat, and server all consume the same map data.

✓
Best first move: a text-editable map file with live reload.

Add Minecraft-like in-game block commands second. Both should write the same format, so the first step is never thrown away.

Four sensible alternatives

Effort is relative to the current C++ prototype—not a production-ready general FPS editor. Estimates assume one experienced developer and include basic tests.

OPTION 01

Text map + live reload

A human-readable file defines bounds, boxes, and spawn points. Edit it in any text editor, then reload from the console.

Build effort2–4 days
Authoring UXGood
diffabletestableserver-safe
  • Fastest route from hard-coded arena to multiple maps.
  • Validation can reject overlapping, inverted, out-of-bounds, or excessive geometry.
  • Coordinates are less intuitive without a preview or grid reference.
Best for: establishing the durable map-data boundary with minimal scope.
OPTION 02

In-game block commands

Enter an edit mode, aim at a grid, place or remove boxes, move spawns, save, and reload—Minecraft creative mode in miniature.

Build effort1–2 weeks
Authoring UXVery good
play-in-placegrid snaplow UI
  • Immediate feel testing: place cover, duel, adjust, repeat.
  • Needs picking/raycasting, selection feedback, undo, save, and edit-mode input rules.
  • Commands alone become awkward; mouse placement plus a few commands is better.
Best for: rapid arena iteration after a load/save format exists.
OPTION 03

Minimal in-game GUI

A small editor overlay provides a block list, numeric transform fields, selection, duplicate/delete, and a top/3D view.

Build effort2–4 weeks
Authoring UXExcellent
discoverablepreciseUI-heavy
  • More approachable and precise than console-only editing.
  • Selection, focus, widgets, camera controls, undo/redo, and gizmos multiply edge cases.
  • Risks becoming a second product that distracts from duel feel and netcode.
Best for: later, if several non-programmers will regularly author maps.
OPTION 04

External editor import

Author geometry in TrenchBroom, Blender, or a tiny web tool, then convert a constrained subset into LG Duel boxes and spawns.

Build effort1–3 weeks
Authoring UXVariable
mature toolsconversionscope risk
  • Leverages mature camera, selection, snapping, and undo workflows.
  • Import rules, coordinate conversion, metadata, and unsupported geometry need clear errors.
  • Too much tool for box arenas unless richer geometry becomes a real requirement.
Best for: a future where maps outgrow axis-aligned block construction.

What the text option could feel like

The exact syntax is a later choice. The important decision is one canonical, versioned model consumed by server, client prediction, collision, combat traces, and rendering.

Small by design

Do not start with arbitrary meshes, materials, lights, scripting, or entities. A useful v1 needs only:

  1. Arena bounds and format version
  2. Axis-aligned solid boxes
  3. Two or more spawn points
  4. Stable IDs for useful validation errors
  5. A deterministic load order
# maps/tracking-room.lgmap
version 1
bounds  min=-15,-11,0  max=15,11,10

# id       min xyz       max xyz
box lane_north  -15,6.5,0    15,11,2
box cover_left  -5,-0.9,0    -3,0.9,1.2
box cover_right  3,-0.9,0      5,0.9,1.2

spawn player_1  -8,-9,2  yaw=0
spawn player_2   8,-9,2  yaw=180

A pragmatic sequence

This sequence keeps every increment usable and avoids committing to a full editor before the actual authoring pain is known.

Phase 01 · foundation

Load + validate

Move the current hard-coded arena into a versioned file. Add clear load errors and simulation tests proving equivalent collision and spawns.

Rough size: 2–4 days
Phase 02 · iteration

Reload + inspect

Add console commands such as map_reload, map_validate, and optional debug labels/bounds. Restrict reload to safe local/dev states.

Rough size: 1–3 days
Phase 03 · creation

Place blocks in-game

Add edit mode, grid raycast, place/delete, spawn placement, undo, and save. Keep editing out of network matches and authoritative ticks.

Rough size: 1–2 weeks

Keep the editor out of the simulation.

Editing is a development workflow. The saved result becomes immutable simulation input when a match starts.

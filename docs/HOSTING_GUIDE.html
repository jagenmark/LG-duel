LG Duel: deploy and operate the Azure server

This project uses a dedicated native UDP server. The default game port is UDP 27960. TCP port forwarding is not needed.

The repository's VM_HOST secret is the source of truth for both deployment and Windows playtest packages. Do not copy a public IP into workflow, script, launcher, or documentation defaults.

1. Deploy from GitHub Actions

Each push to main runs the Deploy Server workflow. It connects using the VM_HOST, VM_USER, and VM_SSH_KEY repository secrets, then updates the checkout, builds lg_duel_server, and restarts the service.

Optional secrets configure the SSH port, deployment path, and clone URL:

VM_SSH_PORT
VM_DEPLOY_PATH
VM_REPOSITORY_URL

If VM_DEPLOY_PATH is unset, the workflow uses $HOME/LG-duel. The server listens on UDP port 27960.

A successful workflow run ends with systemctl --user status reporting lg-duel-server.service as active.

2. Operate and inspect the VM

Use separately provisioned SSH credentials; GitHub secret values cannot be read back from the repository UI. On the VM, manage the user service with:

systemctl --user status lg-duel-server.service
systemctl --user restart lg-duel-server.service
systemctl --user stop lg-duel-server.service
systemctl --user start lg-duel-server.service

Inspect logs and confirm the UDP listener with:

journalctl --user -u lg-duel-server.service -n 100 --no-pager
ss -lun | grep 27960

3. Allow the game port

Azure networking and any guest firewall must allow inbound UDP 27960 to the VM. Do not open an unrestricted port range.

If UFW is active on the VM, allow and inspect the rule with:

sudo ufw allow 27960/udp comment 'LG Duel server'
sudo ufw status numbered

4. Build the Windows playtest package

The Windows Playtest Package workflow builds the ZIP on pushes to main and codex/**, or on manual dispatch.

Its server host defaults to VM_HOST. Manual runs may provide a server_host override; the port defaults to 27960.

The packaging script writes the selected host:port to server-address.txt. Play LG Duel.bat reads only that file and has no hardcoded IP fallback.

Download and distribute the LG-Duel-Windows-x64 artifact. Players must extract the entire ZIP and keep its files together.

5. Connect and verify

Windows players double-click Play LG Duel.bat. A locally built client connects with:

./build/default/lg_duel_client <server-host> 27960

Use the host stored in VM_HOST; do not copy a value into source files. Clients must use a compatible project revision because the handshake validates the protocol version.

Watch journalctl --user -u lg-duel-server.service -f while testing. The prototype accepts two players; both press F3 to ready up.

Troubleshooting

  • Deploy fails before SSH: verify VM_HOST, VM_USER, VM_SSH_KEY, and the optional SSH port secret.
  • Service will not start: inspect systemctl --user status lg-duel-server.service and its journal.
  • Players time out: verify UDP 27960 in the Azure network security rules and the VM firewall, then confirm the service is listening.
  • ZIP points to the wrong host: correct VM_HOST or manually dispatch the package workflow with a temporary override, then download the newly generated artifact.
  • Second player cannot join: check for a stale connection slot in the server log and restart the service if necessary. The intended limit is two players.

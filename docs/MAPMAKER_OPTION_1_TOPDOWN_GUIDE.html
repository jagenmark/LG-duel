LG Duel mapmaking

How to use Mapmaker Option 1 and the top-down .lgmap tool

Option 1 is the text-file workflow: write a small .lgmap file, validate it, preview it from above, then run it through the same map loader used by the game. The top-down tool, or lgmap-topdown-verktyg, is the browser helper that makes that workflow practical.

What Mapmaker Option 1 is

Mapmaker Option 1 means maps are authored as plain text. A map describes the duel arena bounds, solid axis-aligned boxes, and spawn points. It is deliberately narrow: no arbitrary meshes, no lighting, no scripting, no general-purpose level-editor system.

Best use

Fast iteration on small LG duel layouts where collision, beam occlusion, rendering, and server simulation all use one source of truth.

Why it fits this project

Text files are diffable, easy to review, deterministic to parse, and simple to test against the fixed-tick simulation.

What it is not

It is not a full map editor. It is a compact authoring path for the current box-based duel prototype.

The current game map lives at maps/thunderstruck.lgmap. Treat that file as the reference example for naming, scale, and the shape of a valid v1 map.

What the top-down .lgmap tool does

The tool at tools/lgmap-preview/index.html is a local browser utility. It gives you a text editor on the left, a top-down canvas preview in the middle, and validation, stats, and export text on the right.

Input

Paste or edit .lgmap text directly. The preview updates as you type.

Preview

Shows arena bounds, a 1-unit grid, solid boxes, spawn positions, and spawn yaw arrows from above.

Export

Serializes the parsed map into a clean, normalized .lgmap text block that can be copied or downloaded.

How to open it

  1. Open tools/lgmap-preview/index.html in a browser.
  2. Click Open .lgmap and choose a map file, or click Load Sample.
  3. Edit the text in the input pane.
  4. Watch the validation status and top-down preview update immediately.
  5. Use Copy Export or Download when the status says Valid .lgmap.

The .lgmap format

A v1 file is whitespace-separated. Comments start with #. Vectors are written as x,y,z with no spaces inside the vector. 

# LG Duel map format v1.
version 1
bounds min=-15,-11,0 max=15,11,10

box lane_north -15,6.5,0 15,11,2
box cover_left -5,-0.9,0 -3,0.9,1.2
box cover_right 3,-0.9,0 5,0.9,1.2

spawn player_1 -8,-9,2 yaw=0
spawn player_2 8,-9,2 yaw=180
Directive Shape Meaning
version version 1 Declares the file format. Only version 1 is supported.
bounds bounds min=x,y,z max=x,y,z Sets the playable arena volume. Every box and spawn must fit inside it.
box box id min max Adds one axis-aligned solid. Boxes are used by collision, rendering, and LG occlusion.
spawn spawn id x,y,z yaw=degrees Adds a spawn point. The JavaScript tool displays yaw arrows; the C++ loader currently validates the option but ignores yaw in simulation.

Recommended workflow

Start from Thunderstruck

Copy maps/thunderstruck.lgmap or load the sample in the preview tool. Keep the file small and readable while you explore layout ideas.

Block out the arena bounds first

Set bounds before adding geometry. Use a compact duel scale where players can re-engage quickly and the LG beam has meaningful line-of-sight fights.

Add boxes in groups

Build lanes, cover, stairs, and pillars as named boxes. Use stable IDs such as lane_west, cover_mid, and stair_east_3 so review diffs stay understandable.

Place at least two duel spawns

Put initial spawns on solid surfaces with clear but not instant sightlines. Add extra spawns only when they serve round resets or future player-limit testing.

Use the top-down tool as the first validator

Fix every listed issue before testing in the game. The browser parser mirrors the project loader closely, so invalid preview maps are not expected to load in the C++ server either.

Export, save, then run tests

Copy the export text into a .lgmap file and run the relevant map parser tests or the full preset tests before handing the map off.

Validation rules and limits

The current v1 limits are intentionally strict. They keep map data cheap to parse, easy to test, and safe for authoritative simulation.

Rule Limit What to do when it fails
Boxes Maximum 24, at least 1 Merge simple surfaces or remove decorative pieces.
Spawns Maximum 6, at least 2 Keep two primary duel spawns and add extras only when useful.
Coordinates Finite and within +/-1000 Bring the map back to the prototype's local coordinate scale.
Bounds and boxes min must be lower than max on x, y, and z Swap mistaken min/max values and avoid zero-thickness boxes.
Box placement Boxes must be inside bounds and must not overlap Split, move, or resize touching geometry. Stacked stairs should touch faces, not overlap volumes.
Spawn placement Spawns must be inside bounds Move the spawn into the arena volume. Then check in-game that it is on useful walkable geometry.

The validator checks syntax and broad geometry rules. It does not prove the map is fun, reachable, balanced, or spawn-safe. Always playtest after a map loads.

How to design useful LG duel maps

  • Prefer clear fighting lanes over clutter. The prototype is about tracking, movement, and continuous beam pressure.
  • Use cover to break LG contact briefly, not to create maze-like hiding.
  • Keep routes short enough that players re-enter combat quickly after losing line of sight.
  • Make high and low positions matter, but avoid geometry that only works visually and fails collision or beam tests.
  • Use stairs as stepped boxes. Adjacent stair boxes can share faces, but their volumes should not overlap.
  • Name objects by gameplay role. A future reviewer should understand bridge or spawn_deck_west without opening the preview.
  • After browser validation, test movement collision, LG occlusion, spawn flow, and how prediction feels around the geometry.

Good handoff checklist

  • Valid in the top-down preview tool.
  • Readable object names and comments for major layout sections.
  • Compact geometry count under the 24-box limit.
  • Playtested for stuck spots, unfair spawns, and accidental full-map sightlines.
  • Tested with the repository's CMake preset before code or map changes are handed off.
